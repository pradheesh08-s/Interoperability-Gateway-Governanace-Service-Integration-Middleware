# MahaSetu

## Interoperability-Gateway-Governanace-Service-Integration-Middleware

A local hackathon demonstration of a unified public-services gateway. It combines a shared mobile-and-OTP authentication journey with a citizen portal and an operations workspace for connected services.

## Run locally

```powershell
npm install
npm run dev
```

Open the local URL printed by Vite. The development command runs the Vite app and a local Express authentication API together. To create a production frontend build, run `npm run build`.

## Demo flow

- Visit `/` for the MahaSetu landing page and select **Login to MahaSetu**. There is one login; the verified account role determines the destination.
- Seed citizen login: `9876543210`. Seed admin login: `9999999999`. Send an OTP, then choose **Open demo inbox** on the verification page to retrieve the locally generated code. The code is never returned by the OTP request endpoint.
- To exercise citizen registration, use another valid Indian mobile number, verify the OTP from the local demo inbox, and complete the profile. A unique 12-digit Citizen ID is generated by the API, and registration establishes the session without another OTP.
- Admin account creation requires a server-side invitation value. In PowerShell, set `$env:MAHASETU_ADMIN_INVITE_CODE = "your-local-invitation"` before `npm.cmd run dev`; the value is not bundled into the frontend. Existing admin login uses the seeded number above.
- Citizen pages include applications, services, consents, documents, notifications, grievances, and profile. Admin login opens the platform dashboard; its sidebar links to citizens, departments, services, applications, workflows, integrations, API gateway, connectors, data standards, master data, consents, events, notifications, SLA, exceptions, audit, analytics, system health, developer portal, and settings.
- Admin areas not backed by an implemented workflow show searchable, clearly labeled sample module data. They are navigation and UI demonstrations, not configured platform services.

The Express API implements demo OTP challenges using in-memory challenge storage, HMAC-hashed OTPs, attempt/rate limits, unique ID generation, invitation checks, and HttpOnly session cookies. The demo SMS inbox is a local-only substitute for an SMS provider. Users, sessions, audit events, and challenges are memory-only and reset when the API restarts. There is no production SMS integration, persistent database, HTTPS deployment, government connection, or production security review. Do not enter sensitive personal information; this is not a production authentication service.
